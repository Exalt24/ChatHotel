# ChatHotel

![ChatHotel demo: browse hotels, log in, book a room with a live price quote, get rejected on overlapping dates, then edit a weekday surcharge in the admin panel](docs/demo.gif)

*Recorded on a local Docker stack (Rails + PostgreSQL, seeded demo data). Nothing is deployed right now.*

A hotel booking app with weekday-based pricing, availability-checked bookings, and an admin panel. Built solo in a three-day sprint during my Full Stack Developer internship at ChatGenie.PH (Techstars '23).

Guests browse hotels, book a room type for a date range with a live price quote, and leave reviews. Administrators manage hotels, users, bookings, and weekday price adjustments from a separate admin area.

## Features

- **Weekday pricing.** Admins set a surcharge per day of the week in the Pricing Manager. The quote is the number of days in the stay (both the first and last day count) times the room rate plus the surcharge for the check-in weekday. The booking form fetches the quote from the server whenever the dates or room type change (`PricingHelper`, `BookingsController#calculate_price`).
- **Availability-checked bookings.** A booking is rejected when its dates overlap a confirmed booking for the same hotel and room type (`no_double_booking` in `app/models/booking.rb`), so each hotel has one room of each type: single, double, suite. Pages update on navigation (Turbo), not by live push.
- **Accounts.** Registration with email activation, session login with "remember me", and password reset.
- **Reviews.** Logged-in users can leave a 1 to 5 rating and a comment on a hotel.
- **Admin panel.** Dashboard counts, plus manage hotels (with photo uploads), users (grant or revoke admin), bookings (confirm or cancel), and the seven weekday surcharges. Non-admins are redirected away from `/admin`.

## Tech Stack

- **Framework:** Ruby on Rails 8 (Ruby 3.3.2), PostgreSQL
- **Frontend:** server-rendered ERB with Hotwire (Turbo and Stimulus) on an import map, Tailwind CSS, and flatpickr for the date range picker
- **Email:** sent over SMTP when `SMTP_USERNAME` and `SMTP_PASSWORD` are set (see `.env.example`). With no credentials outside production, emails are written to the Rails log instead.
- **Live updates:** none. Action Cable is generated by Rails but no channel or subscription is written.
- **CI:** GitHub Actions runs Brakeman, an import map audit, RuboCop, and the test suite

## Run it locally

You need Docker and nothing else.

```bash
docker compose up --build
```

Then open http://localhost:3000. The first start builds the image, creates the database, loads the schema, and seeds it. To use another host port: `WEB_PORT=4700 docker compose up --build`.

The seed data is Faker-generated: 10 hotels, a handful of customers with bookings, and weekday surcharges (Friday 30, Saturday 50, Sunday 20). Two accounts to try, both with the password `password` (demo data for local use only):

- `guest@example.com` books rooms
- `admin@example.com` opens the admin panel at `/admin`

Seeded hotels have no photos, so the list shows a placeholder image. Admins can upload photos from the hotel edit form.

Emails (booking confirmation, account activation, password reset) land in the container log: `docker compose logs web`. The activation link in the log points at `localhost:5000`, so change the port to the one you are using.

To run the tests against a separate database:

```bash
docker compose exec -e RAILS_ENV=test \
  -e DATABASE_URL=postgres://chathotel@db:5432/hotel_booking_app_test \
  web bash -c "bin/rails db:prepare && bin/rails test"
```

Without Docker you need Ruby 3.3.2 and a local PostgreSQL. Point `DATABASE_URL` at your database, then run `bundle install`, `bin/rails db:prepare`, and `bin/rails server`.

## Deployment

The repository includes a production `Dockerfile` and a `render.yaml` for Render, with Active Storage on S3 in production. The Render service that used to host it is suspended, so there is no live demo at the moment.

## Structure

Standard Rails layout. The domain lives in `app/controllers` (bookings, hotels, reviews, sessions, account activations, password resets, and an `admin/` namespace) and `app/models`, with pricing logic in `app/helpers/pricing_helper.rb`. Docker development files are `Dockerfile.dev` and `docker-compose.yml`.
